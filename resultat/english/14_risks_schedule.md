# Risks and backwards schedule template

The risk assessment is qualitative, not a measured probability model. Key risks include historical HTML/privacy handling, expired source evidence, irrelevant but exact quotations, prompt injection, cold starts/timeouts, thermal load, missing global cancellation and incomplete report provenance. Mitigations include blocked HTML acquisition, genuine source review, explicit refusals, independent human assessment, small thermally bounded experiments and separate approval of application repairs.

Demonstration date D is NOT PROVIDED. Suggested relative milestones, not historical events: D−21: confirm requirements and data boundary; D−14: review safety gaps and authorize any repairs; D−7: freeze code, run regression and finalize analysis; D−3: compile report/appendices and rehearse; D−1: check local operation and source validity; D: demonstrate. Students must confirm dates and responsibilities. Source expiry is not replaced by D.
